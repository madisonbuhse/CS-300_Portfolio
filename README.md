# CS-300_Portfolio

The problem that I was tasked with solving during this course focused heavily on analyzing and determining the appropriate data structure to use in the posed scenario. In the scenario, ABC University was looking to build a program to load a file, store the data in a structure, and then allow the advisors to access course information for students. Prior to writing any pseudocode or analysis, I studied the provided course materials which examined basic data structures, common abstract data types, and the standard libraries which are provided in different programming languages. This then led me to delve into various searching and sorting algorithms and how their logic can or can't be implemented within each data structure. By examining the various structures and methods which apply to them, this provided me with a lens from which to view the problem which was posed to me. 

After establishing an understanding of the functionality of data structures - more specifically that of utilizing a linked list, hash table, or binary search tree - I took note of what ABCU required in their program. They needed a way to load, parse, and store data from a file. That data then needed to be logically sorted to eventually be searched, printed, inserted, or deleted safely and securely. These requirements informed my analysis, I needed to find a data structure that would reliably perform these tasks with the optimal balance of runtime performance, memory, and maintaining a clear written and logical structure for the program that others could alter in the future. Taking these aspects of performance, logic, and readability into consideration, I eventually landed on the binary search tree as the data structure I would use to form the base logic and storage structure of ABCU's program.

While writing the pseudocode for the various data structures and how they would be implemented to load, parse, and store the file data, I initially struggled with the internal logic of the methods and how the structure itself allowed or altered different abilities of the program. I found that overall, each method uses similar logic to load the data, however, the ways in which each structure creates storage and then inserts that data varies. For example, in a hash table, each node which holds course data within the table is assigned a hash value which determines not only the position of the data within that table, but also the way that one can look up and access that node. Whereas within a binary search tree, the data node is identified by its course number, which determines its position within the tree, and necessitates a differing type of logic to that of the hash table to look up and access the node. To move forward past these struggles, and to ultimately come to an informed decision on what data structure would be optimal for the program, I learned the importance of having a thorough understanding of data structures, their internal logic, and how that influences the program's runtime and memory usage. Without that understanding, the structure of the program would be disjointed, illogical, and suboptimal for its intended use. This overall instilled in me how a holistic approach must be taken when writing code. Where the needs of the client must be considered along with the functionality, and optimization of the data structure in which you choose that will create the optimal solution for both those who will use the program, and who will maintain the program.
